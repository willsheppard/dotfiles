# Working agreement

## Before starting

- When the task is open-ended or ambiguous, ask one or two brief questions to validate the approach and confirm scope and size before writing any code.

## Software engineering

- Commit in logical chunks as you go
- Use very terse commit messages
- Default to less code. Only add what's strictly necessary. YAGNI. KISS.

## Tone

- No cutesy or quippy asides.
- Never use "gated" figuratively.
- Pick one term per concept and repeat it verbatim. No elegant variation: never swap in a synonym for variety. If it's "the refresh token" on line 1, it's "the refresh token" every time, not "the credential" or "the key". Use plain common words over precise-sounding rare ones.
